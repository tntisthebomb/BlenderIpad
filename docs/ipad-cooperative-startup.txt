Experimental Blender iPad cooperative-startup candidate

This full package contains a NEW native engine. Replace all files in the
existing WorldWideWeb Blender folder, including blender-core.js, .wasm and
.data. Keep serving the same localhost address/port to retain saved projects.
Install using http://localhost:8080/ipad-update.html, then close all Blender and
updater tabs/Home Screen windows before reopening http://localhost:8080/.
Press Start once. The statistics panel identifies v10 and counts native yields and Python checkpoints.

Interactive redraws batch intermediate copies and small texture uploads in the
same command buffer. A bounded buffer pool reuses submitted-frame allocations;
unsubmitted work cannot share those buffers. Shared viewport contexts reset
their upload arenas at their own frame boundaries; repeated viewport/scissor
state calls within a pass are skipped. Display resolution, Blender tools
and render features are unchanged. Automated orbit checks cover both Object and
Edit Mode, with limits on submissions and fresh buffer allocations per frame.

This build preserves a separate presented front framebuffer for native screen
thumbnail reads. Two-finger touch intent avoids selecting before orbiting.
Native-generated shader translations are matched to the exact engine; a
mismatch safely uses the native compiler. Editing diagnostics continue after
the first frame and uncaught runtime errors retain project recovery controls.

Native initialization, Python module loading/registration and shader/pipeline
creation can yield during startup, allowing browser timers/painting to run. Canvas presentation
refreshes the acquired surface after these yields. Input and resize callbacks
cannot re-enter native initialization while it is suspended. Yielding stops
after the first content frame; no render functionality is disabled.

The package must pass native/Python suspension, canvas pixel/ownership, editor,
modeling, rendering, recovery and whole-launch responsiveness checks before
delivery. The responsiveness test adds 60 ms to each real render pipeline call
and requires timer/paint opportunities with no main-thread gap over 5 seconds. These tests do not
establish physical iPad acceptance. An individual translation or CPU setup
stage can still block, and this does not guarantee a successful iPad launch.
If the device becomes unresponsive, close Blender rather than repeatedly
restarting it. Reopen without pressing Start and download the device report.
Do not clear Safari website data; export project backups when available.

GPL-3.0-or-later. Corresponding source and dependency notices accompany the
accepted build as a separate artifact on the same GitHub Actions run page.

Blender iPad pipeline check v2 (not a Blender build)

The original outline fragment shader compiled on the physical iPad in v1.
That does not establish why Blender's full startup failed. This check replays
the captured pipeline with its actual vertex shader, layout and blend state,
through both the synchronous and asynchronous WebGPU pipeline APIs. It tests
default device limits and Blender's actual device feature/limit negotiation.

Keep all Blender engine tabs closed. Do not clear Safari website data.

Extract this small ZIP. Move ONLY ipad-pipeline-check.html into the existing
Blender folder that WorldWideWeb serves (the folder containing index.html).
Do not replace existing engine files or change the selected server folder.

Keep WorldWideWeb running and open Safari at:
http://localhost:8080/ipad-pipeline-check.html

Tap Check pipeline once. When finished, use Copy report or Download report
and send the report in the chat. If the whole iPad slows down, close the tab.

The page is self-contained and makes no engine requests. It uses two graphics
devices sequentially, destroys them after checking, and does not allocate scene
textures, start Blender, access projects, register a worker or install anything.
Its 30-second deadline does not automatically retry.

Pipeline captured from the delivered engine, source commit:
893f6163652f5cde223f9781a61ef4931f4b3444
https://github.com/tntisthebomb/BlenderIpad/actions/runs/38705147615/artifacts/11958485469
Both shader hashes are included in the report and the embedded source fixture.
Chromium success does not establish Metal compilation or physical startup.
